# 通假字生成工具 · Word Obfuscation

把一段中文里的每个汉字，替换成**偏旁不同、主体相同的「形近字」**。整句话一眼扫过去仍能联想出原意，可逐字细看时，每个字又都不太对劲。

> 例如：`操你妈逼` → `懆称冯福`
>
> 「操 / 懆」同含「喿」，「你 / 称」同含「尔」，「妈 / 冯」同含「马」，「逼 / 福」同含「畐」——只是偏旁被换掉了。

## 在线体验

部署在 GitHub Pages 上：把仓库的 Pages 指向主分支根目录即可访问。

## 它是怎么做到的

汉字大多是「合体字」，由一个**偏旁**（出现频率高、可替换）和一个**主体**（出现频率低、有辨识度）组成。本工具：

1. 用 **IDS（表意文字描述序列）** 把每个汉字拆成结构部件，例如 `操 = ⿰扌喿`。
2. 找出每个字里最有辨识度的「主体」部件，并记录它所在的**视觉位置**（左 / 右、上 / 下、内 / 外）。
3. 把「主体 + 位置」相同的字归为一组，组内的字互为候选——它们共享主体，只是偏旁不同。
4. 转换时，对每个字从它的候选里**随机**挑一个。所以多点几次「开始转换」，结果会不一样。

「位置」这一维度很关键：它让 `逼（⿺辶畐）` 能匹配到 `福（⿰示畐）`（「畐」都在右侧，哪怕外层结构不同），同时把 `劋（⿰喿刂）` 排除在 `操` 的候选之外（这里「喿」在左侧，而 `操` 的「喿」在右侧）。

## 项目结构

```
IDS-UCS-Basic.txt   原始数据：CJK 基本汉字（U+4E00–U+9FA5）的 IDS 拆字表
utils.py            IDS 解析工具（结构树解析、部件提取、视觉位置判定）
build.py            数据管线：拆字 → 生成 mapping.json
mapping.json        前端使用的映射表 { 原字: [候选字, ...] }
index.html          单页界面（内联 CSS）
app.js              前端逻辑：加载映射、随机替换、计数、复制
```

## 重新生成数据

需要 Python 3（标准库即可，无第三方依赖）：

```bash
# 全流程：拆字 + 生成映射
python build.py

# 或单独运行某一阶段
python build.py --stage basic     # 仅生成 all_basic_hanzi.json（中间产物）
python build.py --stage mapping   # 仅由中间产物生成 mapping.json
```

可在 `build.py` 顶部调参：

- `MAX_CANDIDATES`：每个字最多保留多少个候选（控制 `mapping.json` 体积）。
- `MIN_BODY_LEN` / `TRIVIAL_BODIES`：过滤掉过于平凡、没有辨识度的「主体」。

## 本地预览

`app.js` 通过 `fetch('mapping.json')` 加载数据，需要在 HTTP 环境下打开（不能直接双击用 `file://` 打开）：

```bash
python -m http.server
# 然后访问 http://localhost:8000
```
